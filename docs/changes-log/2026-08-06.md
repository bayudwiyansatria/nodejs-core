# 2026-08-06 — Extraction into a package

Turned this repository from the Node.js library template into `@bayudwiyansatria/core`, the kernel, by lifting
`src/core/system/` out of `cloudflare-boilerplate`.

## Scaffold replaced first

This repository was on the older template generation and could not have built the moved code as it stood:

- `.eslintrc.json` + `.eslintignore`, which ESLint 10 no longer reads → flat `eslint.config.ts`
- `main: lib/index.min.js` under `"type": "module"` — the CommonJS-parsed-as-ESM bug — → `.cjs`/`.mjs` outputs
- no `exports` map, a stub `typedoc.json`, a root `Dockerfile` instead of `docker/`
- TypeScript 4.7, ESLint 8, TypeDoc 0.23

Ported the newer scaffolding from `nodejs-cloudflare`: flat ESLint config with the three custom documentation rules,
four Rollup outputs, the tsconfig set, TypeDoc with `treatWarningsAsErrors`, Jest, the docs site image, and the
`.github/` workflows.

## Moved in

45 files, flattened by one level — the `core/system/` prefix is dropped because everything in this package *is* the
kernel:

`capabilities/` (26 including `noop/`), `config/` (8), `observability/` (2), `security/timingSafeEqual.ts`,
`errors/MissingCapabilityError.ts`, `utils/` (4), `Service.ts`, `APIResponse.ts`.

Verified before deleting the originals: every one of the 90 files under the boilerplate's `src/core/` has a counterpart
in one of the two new packages, including the untracked `SqlTarget.ts`.

## Changed in the move

- **`configure()` added**, and `resolve()` inverted to read a registry rather than import the application's `config/`.
  New files: `config/configure.ts`, `config/ConfigurationRegistry.ts`, `errors/ConfigurationError.ts`. The per-field
  merge semantics and the ignore-`undefined` rule carry over verbatim — they are the documented contract.
- **`resolve()` is generic over the settings shape** (`resolve<KVSettings>('kv')`), because the kernel cannot know the
  assembled surface. The caller declares what it expects back.
- **`Logger.fromEnv(env: Env)` → `fromEnv(env: { LOG_LEVEL?: string } | null | undefined)`**. The only real platform
  type reference in the package; the rest were prose.
- **`Signature`'s key type derived from `crypto.subtle`** rather than the ambient `CryptoKey`, which is only global when
  a runtime-specific lib is in scope. It never reaches the public surface.
- **`systemDefaults.logging.service`**: `'cloudflare-boilerplate'` → `'app'`.
- 39 specifiers rewritten from `core/system/…` to the `@/*` mapping.
- In-package `{@link core/system/X!Y}` references collapsed to bare symbols; cross-package ones became prose.
- Barrel `@module` blocks rewritten — they described a three-bucket layout that no longer exists.

## Tooling

- Added a kernel-purity ESLint rule: no `@cloudflare/*`, `hono`, or `cloudflare:*` anywhere in `src/`. This is the
  boundary that made the extraction possible, kept enforced.
- Bumped `@types/node` to `^22`. Node 18 is past end of life and its types predate the global `crypto` declaration that
  `Signature` needs.
- Turned off `sourcemap` for the declaration bundle. `rollup-plugin-dts` emits a map with `sources: []` and empty
  `mappings` — inert, excluded from the tarball by `files`, and it *crashes* TypeDoc in any downstream package that
  resolves a symbol from here (`path.resolve` on the `undefined` it reads out of that empty array).

## Tests

85 specs across nine suites, replacing the template's three. Highest-value coverage:

- `configure`/`resolve` merge contract, both `ConfigurationError` paths, and non-mutation of the registered defaults
- `timingSafeEqual` over the cases an early return gets wrong, including equal-`.length` strings of different byte length
- `Signature` with a negative case per forgeable input, plus secret rotation against the key cache
- `Logger` threshold, `LOG_LEVEL` override, context inheritance, and `Error` expansion in payloads
- `MissingCapabilityError` caught as the base from a subclass defined elsewhere — the cross-package contract

Coverage 97.6%.
