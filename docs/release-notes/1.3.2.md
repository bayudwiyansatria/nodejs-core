# Release Notes

## Version 1.3.2

### 📅 Release Date

October 26, 2026

### 📖 Overview

This release updates development dependencies to address published vulnerabilities, including two critical JavaScript
injection flaws in Handlebars. The lockfile moves Handlebars from 4.7.9 to 4.7.10 and includes security updates for the
HTTP client, YAML and Markdown parsers, brace expansion, and JavaScript serializer used by development tools.

The repository already had a formatter, but passing `npm test` did not require using it. ESLint checked production
source and skipped the tests, and neither tool supplied the logical spacing that makes a function or test easy to
follow.

This release puts formatting into the test command, extends linting to test files, and records the local readability
conventions. It also shortens repetitive comments and clarifies the configuration guide. The code consumers execute and
the public API remain unchanged.

The [October 26 changes log](../changes-log/2026-10-26.md) records the reasoning behind the cleanup and why short build
configuration lists keep their existing line breaks.

### ⚠️ Breaking Changes

- **None.** No export, method signature, configuration field, or response shape changed.

### 🚀 Features

- **None.** No new runtime capability or public export.

### 🔧 Enhancements

- **`npm test` checks formatting first.** The new `format:check` command checks the same files that `format` writes,
  covering source, tests, Markdown, and the configured tooling files. Generated output and the dependency lockfile stay
  excluded.
- **Linting includes `test/`.** Both `lint:run` and `lint:fix` now cover source and tests. Jest globals are declared for
  test files, and spacing rules separate declarations, control flow, returns, and class members.
- **Comments focus on the contract.** `Logger`, `LogFields`, `Retry`, `Json`, and `List` retain public JSDoc and useful
  examples while removing repeated explanations. Test introductions that restated the assertions were removed.
- **Build lists stay expanded.** `rollup.config.ts` remains outside Prettier so `include`, `output`, and `plugins` keep
  one entry per line. `CODEOWNERS` is explicitly excluded from formatting to preserve its ownership-pattern syntax.

### 🐛 Bug Fixes

- **Formatting commands use shell-compatible quoting.** Double-quoted globs let npm's Windows shell pass the patterns to
  Prettier correctly.
- **Documentation links match the release.** The README points to these notes, and the developer book no longer links to
  the deleted October 4 engineering record.

### 🔐 Security

**Two critical Handlebars vulnerabilities are fixed by the lockfile update from 4.7.9 to 4.7.10.** Handlebars is a
transitive development dependency of `ts-jest` in this repository.

- **[CVE-2026-106445](https://github.com/handlebars-lang/handlebars.js/security/advisories/GHSA-p8wg-vrv2-v86f)** —
  Critical, CVSS 4.0 score 9.2. An own-property check could bypass the prototype-access deny list and expose the
  Function constructor when prototype methods were enabled. A controlled template could then execute arbitrary
  JavaScript.
- **[CVE-2026-106446](https://github.com/handlebars-lang/handlebars.js/security/advisories/GHSA-8r5x-fm3f-whwj)** —
  Critical, CVSS 3.1 score 9.8. Incomplete AST validation could let untrusted objects passed to `compile()` or
  `precompile()` inject JavaScript. Both critical advisories affect 4.7.9 and are patched in 4.7.10.

The dependency refresh also addresses these advisories:

- **Handlebars 4.7.10:**
  [CVE-2026-106444](https://github.com/handlebars-lang/handlebars.js/security/advisories/GHSA-xw65-4hp5-5hc7), unsafe
  inline embedding of precompiled templates.
- **Undici 7.30.1:** the [upstream security release](https://github.com/nodejs/undici/releases/tag/v7.30.1) fixes
  CVE-2026-87018, CVE-2026-109383, CVE-2026-109829, and CVE-2026-109869, covering TLS handling, cache isolation, and
  response-processing failures. It also fixes CVE-2026-87029, CVE-2026-109841, CVE-2026-109924, and CVE-2026-109932 in
  decompression, integrity checks, EventSource, and WebSocket buffering. The lockfile advances from 7.30.0 to 7.30.1;
  the package override remains `^7.30.0`.
- **Brace expansion 5.0.12 and 1.1.21:**
  [CVE-2026-102276](https://github.com/juliangruber/brace-expansion/security/advisories/GHSA-6j4f-fj2g-mc7p),
  [CVE-2026-102278](https://github.com/juliangruber/brace-expansion/security/advisories/GHSA-qhr7-859c-m2p7), and
  [CVE-2026-102277](https://github.com/juliangruber/brace-expansion/security/advisories/GHSA-q2hr-2g5m-vwhr), denial of
  service through uncontrolled recursion or quadratic processing. The affected lockfile versions were 5.0.9 and 1.1.18.
- **Markdown-it 14.3.3:**
  [CVE-2026-111758](https://github.com/markdown-it/markdown-it/security/advisories/GHSA-gfr2-rv44-r23c),
  [CVE-2026-111759](https://github.com/markdown-it/markdown-it/security/advisories/GHSA-r7fv-28h4-cvq7), and
  [CVE-2026-111766](https://github.com/markdown-it/markdown-it/security/advisories/GHSA-vfgh-jcmw-g37q), quadratic-time
  processing in link references, smartquotes, and inline HTML. The lockfile previously resolved 14.3.0.
- **Serialize-javascript 7.1.4:**
  [CVE-2026-115897](https://github.com/yahoo/serialize-javascript/security/advisories/GHSA-m5mm-p8h7-m29v), script-tag
  escaping at the end of serialized function bodies. The lockfile previously resolved 7.0.7; the advisory's patch is
  included from 7.1.3.
- **Js-yaml 4.3.2:** [CVE-2026-84375](https://github.com/nodeca/js-yaml/security/advisories/GHSA-2883-xcg3-v3hh), CPU
  exhaustion through empty merge sources. Overrides for `front-matter` and `@istanbuljs/load-nyc-config` select
  `^4.3.2`, removing the vulnerable 3.15.1 copy under the coverage configuration loader.

These dependencies belong to the test, build, and documentation tools. The published library has no third-party runtime
dependencies. `npm audit --package-lock-only --json` against the npm registry reported **zero vulnerabilities** on
October 26, 2026.

### 🧪 Tests

**190 tests across 13 suites**, unchanged from 1.3.1. Formatting, linting, package bundles, declarations, the TypeDoc
API reference, and the HonKit developer book were checked for this release.

Local verification uses Node.js 26.12.1. Jest runs with `--runInBand` because the environment blocks worker processes,
and TypeDoc uses its direct CLI entry point for the same reason. Node.js 22 remains the repository's development and CI
baseline; it was not available for local verification.

### 📚 Documentation

- The [readability guide](../reference/readability.md) gives examples of logical spacing, test structure, comments, and
  review checks.
- The [configuration reference](../reference/configuration.md) explains registration, field-level overrides,
  initialization order, and missing settings in the order callers encounter them.
- The README, contributing guide, and agent instructions describe the updated checks and writing conventions.

### ⬆️ Upgrading

```bash
npm install @bayudwiyansatria/core@1.3.2
```

No application changes are required. Contributors should run `npm run format` and `npm run lint:fix` before `npm test`
when existing changes fail the new checks.

### 🚨 Known Issues

- **Local verification did not use Node.js 22.** The checks above ran on Node.js 26.12.1; the CI baseline still requires
  its own run.
